# The Dungeons — Decompressed Memory Map ($0800–$652A)

Derived by emulating the depacker stub in `the_dungeons.prg` and capturing the
resulting runtime image. All addresses below refer to this decompressed image
(`the_dungeons_unpacked.prg` / `mem_snapshot.bin`), NOT the original compressed
file offsets.

| Range | Size | Contents | Confidence |
|---|---|---|---|
| `$0800`–`$083F` | 64 | Dead/leftover space, mostly zero. **Not** real data. | High |
| `$0840`–`$1140` | 2304 | **Sprite data pool.** 36 sprite blocks (VIC block #33–68, 64 bytes each). Visually confirmed — spider, centipede, worm, dragon/bat, the player figure, key, portcullis/bars, harp/scroll. Matches monster names in the BASIC `M$`/`MN` DATA statements exactly. Block numbers are driven directly by `POKE 2040..2047,<block>` sprite-pointer pokes and by `POKE(64*N+I),...` copy loops in the BASIC source (used for sprite animation — copying "template" frames 64–68 into "active" slots 60–63). | Confirmed (rendered `sprite_sheet.png`) |
| `$1140`–`$1200` | 192 | Custom character/tile bitmaps (alternating `FF 00` and space-run patterns) — likely wall/gate/bars decoration tiles for the dungeon display. | Medium — structurally clear, semantics inferred |
| `$1201`–`$1217` | 23 | An embedded, self-contained one-line BASIC fragment: `10 POKE8192,0:POKE44,32:RUN`. **Solved:** this is a "press RUN to restart" mechanic. BASIC line 778 does `POKE44,18:END`, deliberately pointing TXTTAB at `$1200` before ending; typing `RUN` afterward executes this fragment, which points TXTTAB back at `$2001` and restarts the game. Not dead code — both halves are load-bearing. | Confirmed |
| `$1218`–`$125F` | 72 | **Machine code: tape SAVE/LOAD routines.** Confirmed via disassembly — calls real KERNAL vectors `$FFBA` (SETLFS), `$FFBD` (SETNAM), `$FFD8` (SAVE), `$FFD5` (LOAD). Exactly matches `SYS4640` (save, BASIC line 712) and `SYS4676` (load, BASIC line 1142) called from the main program. Saves/loads the game-state block at `$1C00`–`$2000` under the filename "DATA1". | Confirmed |
| `$1260`–`$13FF` | ~416 | A lookup/translation table — sequences of ascending byte runs (`$40`–`$49`, `$A1`–`$A4`, `$A5`–`$AF`, `$B0`–`$DD`...) separated by padding. Structurally a table, not bitmap graphics. Exact semantic purpose (screen-code / sprite-pointer / message-index mapping) not yet nailed down. | Structure confirmed, semantics open |
| `$1400`–`$1C00` | 2048 | **Standard C64 character ROM copy** (full 256-char uppercase/graphics set) — confirmed visually: legible `@ABCDEFGHIJKLMNOPQRSTUVWXYZ`, digits, punctuation, PETSCII line-drawing glyphs. Copied into RAM so the game can mix system text with redefined graphics characters while banking BASIC ROM out. | Confirmed (rendered `charset_1400_2000.png`) |
| ~`$1800`–`$2000` | ~2048 | This is the game's working-storage block (`NAME`, `SR`, `MS`, `T`, `TR`, `R` scratch arrays, computed from BASIC line 243's `D=30*256:R=D-99:TR=R-18:Q=18:T=TR-100:MS=T-100`), and critically the **dungeon exit matrix** at `D` (`$1E00` onward, indexed `PEEK(D+room*4+direction)`, BASIC lines 161/163). Everything except `D` gets rewritten by the BASIC program at runtime; `D` never does, so it must be preserved as static data. | Confirmed |
| `$2001`–`$6268` | 17000 | **The full BASIC program** — 476 lines, tokenized. This is the entire game "THE DUNGEONS" by Brian and Marian Clark (C) June 1983: game loop, combat, inventory, dungeon layout (`DATA` at lines 3100–3140), item table (4000–4020), message strings (5000–5060). Fully detokenized — see `basic_listing.txt`. | Confirmed |
| `$6271`–`$646C` | ~507 | ASCII-encoded numeric records (short binary headers + comma-separated numbers) and quoted item-name strings (`"DAGGER"`, `"MAGIC AXE"`, `"HELMET"`, ...) that **do not appear anywhere** in the main 476-line program. Confirmed unreferenced by any live code path. Likely cut/unused item content from an earlier build rather than decompression noise - the data is clean, structured item records, not high-entropy garbage. Kept as `leftover_items.asm` for historical reference / a possible future "restore the cut items" enhancement. | Confirmed unreferenced; origin is cut content, not a decompression artifact |
| `$646C`–`$64FF` | ~147 | Filler padding, solid run of `$C7` bytes. | Confirmed (padding) |
| `$6500`–`$652A` | 43 | **ML entry stub.** Sets zero-page `$2B/$2C` (TXTTAB) = `$2001`, `$2D/$2E`,`$2F/$30`,`$31/$32` = `$6500`, then `JSR $A660` (BASIC LINKPRG), `JSR $A68E` (BASIC CLR-equivalent), `JMP $A7AE` (BASIC statement dispatcher) — hands off from the depacker straight into running the BASIC program at `$2001`. This is the true "game start" instruction sequence. | Confirmed (traced via emulation) |
